Claude Code in a real day

From an empty folder to production, in 45 minutes.

LLM Praxis, part 2. Part 1 gave the words. Now we use them.

The playground

  • It looks like a company: a GitLab with pipelines.
  • Two servers: test and prod.
  • Company TLS and SSH.
  • Everything runs on this Mac.

The app

  • A small Go web app, like traefik/whoami.
  • It shows the host name, the IP addresses and the request headers.
  • A merge to main deploys to test.
  • prod is a manual job.

Three iterations

1. Plain text

plan, build, review, merge request, deploy to prod

2. JSON

a new parameter, then an outage on prod

3. Web UI

a plugin and the browser

Each slide: one or two commands, then the prompt. Then we switch to the terminal.

MCP or CLI?

  

    
MCP
Typed tools with their own login. Good for merge requests.

    
CLI
All that a terminal can do, with your credentials. Good for glab and ssh.

  

  
The MCP server cannot start a manual job. glab can.






  
The settings, explained

  
    
    
  • A hook loads .env before each command.
    • 
    
  • A deny rule: Claude may not read .env.
    • 
    
  • Ask rules: Claude Code asks before each way to start the prod job.
    • 
  

  






  
The token goes into .env

  
    
    
  • You make the token in GitLab: the api scope, one day.
    • 
    
  • You put it into .env. Git ignores that file.
    • 
    
  • Claude never sees the value in the chat.
    • 
    
  • The deny rule and the CLAUDE.md line are a guard, not a wall.
    •

Recap

  
    
    
  • CLAUDE.md grew by a few lines, each with a reason.
    • 
    
  • Plan, build, review, merge, deploy.
    • 
    
  • MCP for typed tools. CLI for the rest.
    • 
    
  • Rules guard the risky step.
    • 
    
  • One task, one context.
    • 
  






  
What does not go into CLAUDE.md

  
    
    
  • Secrets and tokens.
    • 
    
  • Long explanations.
    • 
    
  • What Claude can read from the code.
    • 
  

  
At most about 15 lines.






  
Phrases to stop writing

  

    
Instead ofWrite

    
"Make it better"The goal, and how you check it

    
"Be careful"A limit: what not to touch

    
"You are an expert"The context Claude cannot guess

    
"Fix it"What fails, and the command that shows it
