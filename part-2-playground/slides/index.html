Model and harness

A model is the brain. It reads text and writes text.

A harness is the hands for the brain: the program around the model, with the tools, the loop, the permissions and the context.

An agent is the two working together.

Claude is a model. Claude Code is a harness.

  you
   │  prompt
   ▼
┌─ harness: Claude Code ──────────────┐
│  tools  permissions  context  files │
└───────┬──────────────────▲──────────┘
        │ request          │ answer or tool call
        ▼                  │
┌─ model: Claude ──────────┴──────────┐
│  predicts the next text             │
└─────────────────────────────────────┘

The harness runs the tool call, adds the
result and asks the model again.

What you can choose

The harness and the model are two choices.

The same model acts differently in a different harness, because each harness has its own system prompt and tools.

Today: Claude Code with Claude models.

Harnesses

  • Claude Code
  • Codex CLI
  • Gemini CLI
  • OpenCode
  • Cursor

Models

  • Claude: Haiku, Sonnet, Opus, Fable
  • OpenAI: Luna, Terra, Sol, Astra

Words we use today

You see these words in the interface of Claude Code.

The context grows with each turn. Each prompt, answer and tool result stays in the window and goes out again with the next request.

The bigger the context, the higher the cost of each request.

token           a small piece of text;
                the unit of size and cost

context window  all the text the model sees
                in one request

tool            an action the harness runs for the
                model: read a file, run a command

permission      a rule: what the harness
                can do without asking you

CLAUDE.md       project notes, loaded
                in each session

MCP             a way to connect outside
                systems as new tools

The playground

It simulates the environment of a company or a startup, and it runs on your own computer.

  • GitLab, with a runner for the pipelines
  • Docker, where the runner starts its jobs
  • Two servers: test and prod
  • Its own HTTPS certificates and SSH keys

Each part is a container in one Docker Compose project.

Install

Claude Code is a program in your terminal.

The native install updates itself. A Homebrew install does not.

Or with Homebrew

brew install --cask claude-code

Open a new terminal, then check

claude --version

Pick the model and the effort

A bigger model plans better. A smaller model is faster and costs less.

Low effort for a simple edit. High effort for a hard bug or a design.

A line at the bottom of Claude Code. A script you choose prints it.

You tell Claude what to show, and Claude writes the script.

Most keyboard hints in the footer then disappear.

MCP or CLI?

    
MCP: typed tools with their own login. Good for merge requests.

    
CLI: all that a terminal can do, with your credentials. Good for glab and ssh.

    
The MCP server cannot start a manual job. glab can.

  

  


MCP   open a merge request, read an issue
CLI   start a manual job, connect with ssh

  






  

    
The settings, explained

    
    
      
  • A hook loads .env before each command.
    • 
      
  • A deny rule: Claude cannot read .env.
    • 
      
  • Ask rules: Claude Code asks before each way to start the prod job.

The token goes into .env

    
    
      
  • You make the token in GitLab: the api scope, one day.
    • 
      
  • You put it into .env. Git ignores that file.
    • 
      
  • Claude never sees the value in the chat.
    • 
    

    
The deny rule and the CLAUDE.md line are a guard, not a wall.

  

  

    
(umask 077; printf 'GITLAB_TOKEN=%s\nGITLAB_HOST=gitlab.playground.localhost\n' "$(pbpaste)" > ~/llm-praxis-demo/whoami/.env)

A rule matches what is written

Phrases to stop writing

    
Each phrase on the left of the terminal gives Claude nothing to work with. Give it the line on the right.

  

  


"Make it better"       the goal, and how you check it
"Be careful"           a limit: what not to touch
"You are an expert"    the context Claude cannot guess
"Fix it"               what fails, and the command
                       that shows it
